## 实现与操作流程

```text
加载已拟合APS权重 → 恢复21题保存分数 → 原对象恢复自然注意力
→ 仅44张量求梯度 → batch4反传一次、0更新
→ 保存并回读全部101张量 → 同题评分恢复及冻结检查
```

转换与保存模块为`src/goqueen/warm_qk.py`，工程入口为`scripts/check_aps_warm_qk_engineering.py`。训练入口`scripts/train_aps_warm_qk.py`和外部启动器`scripts/run_aps_warm_qk.py`已实现；本阶段未启动完整训练生命周期。

Claude指出，APS拟合的运行记录显示44个Q／K／query_norm张量始终未更新，保留seed42初始化；这里的起步优势来自其余APS参数的已拟合状态，不表示Q／K已经学会选点。

未训练的投影仍可随文字和棋盘改变输出，不能据此断言注意力均匀或与问题无关。

本次使用Qwen3-0.6B、11组`[361,768]`专家特征；注入层为`[0,3,5,8,11,14,16,19,22,24,27]`。CPU4、FP32、math SDPA，Python3.12.14／torch2.14.1／transformers4.57.6／numpy2.5.3。实际过程生产器为`outputs/aps-warm-qk-engineering/producer-at-run.py`，从同一外部时钟起计；240秒软预算包含导入、加载、哈希、保存及报告，不自动重试或扩展。该记录对应本次已结束操作，不是重跑指令。

工程权重标记`variant=m`、`training_recipe=aps_warm_qk`、`engineering_only=true`、`updates=0`，不携带APS单点路由合同。保存时临时恢复全部101的加载标志，既有加载器返回后恢复44／57分组。此过程使用同一模型和同一进程，没有另建真实基础模型进行独立恢复。通用M加载器仅保证架构与张量兼容，不把`engineering_only`作为已训练权重的资格判据；该零更新文件不得作为拟合结果使用。转换后的当前入口只调用自然评分函数，不沿用APS的`point_indices`调用；通用M前向不保证拒绝此类多余参数。
